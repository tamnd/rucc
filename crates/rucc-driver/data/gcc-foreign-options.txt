# The options gcc 16 takes for C++ or Objective-C and not for C, one to a line. src/foreign.rs reads this to answer such an option on a C or assembly unit the way gcc does.
#
# gcc-foreign-options.py beside this file wrote the lines from gcc's own option files:
#
#   python3 gcc-foreign-options.py gcc-16/gcc/c-family/c.opt gcc-16/gcc/common.opt gcc-14/gcc/c-family/c.opt gcc-15/gcc/c-family/c.opt
#
# The columns are separated by a tab:
#
#   1. The name, without the dash. A name that ends in = or - takes its value joined to it.
#   2. The languages gcc names in its warning, for a gcc built with the C, C++ and Objective-C front ends, which is what the BSDs build. A gcc with the D front end says C++/D/ObjC++ for some of them.
#   3. exact or joined for an option gcc complains about, ignore for one it takes and says nothing about, and removed for one it says is no longer supported.
#   4. neg when gcc also takes the -fno- or -Wno- form.
#   5. The option gcc reads it as, with the value for the positive and the negative form, or - when it is its own option. gcc names that option in its warning.
#   6. The first gcc that has the option, 15 or 16, which makes it an unknown option under a claim of an older one, or 0 when gcc 14 has it.
#
# Only the -f, -W, -std= and -nostdinc++ options are here, which are the ones a build passes. gcc 16 has RejectNegative on -Woverloaded-virtual=, so -Wno-overloaded-virtual is -Woverloaded-virtual=0 in its warning, where gcc 15 and older say -Wno-overloaded-virtual=0. To move to a newer gcc, run the command with its files and replace the lines below.
